# Back-End Routes

## Overview
Defines the Express `Router` modules that map HTTP endpoints to authentication/authorization middlewares, domain controllers, and inline validation/persistence handlers for clinic ERP operations and CFDI invoice requests.

## Interface
- Appointment router (`[appointment.routes.js:router]`): Public `GET /treatments`; authenticated `POST /register/appointment`, `GET /user/appointment`, `GET /user/appointment/:id`, `GET /availability`; admin-only `GET /admin/appointments`, `PATCH /admin/appointments/:id/cancel`, `POST /admin/block-slot`, `DELETE /admin/block-slot`, `POST /admin/block-range`, `DELETE /admin/block-range`.
- Auth router (`[auth.routes.js:router]`): Public `POST /register`, `POST /user/login`, `POST /login` (Google Sign-In), `GET /verify-email/:token`, `POST /resend-verification`, `POST /forgot-password`, `POST /reset-password/:token`; authenticated `GET /user/profile`, `POST /user/patient-type`.
- Contact router (`[contact.routes.js:router]`): Authenticated `POST /`.
- Invoice request router (`[invoiceRequest.routes.js:router]`): Authenticated `GET /:id` and `POST /:id` for patient CFDI invoice requests scoped to owned appointments.
- Mercado Pago router (`[mercado_pago.routes.js:router]`): `GET /`, authenticated `POST /proccesPay`, and public `POST /webhook`.
- Clinic ERP operations router (`[operations.routes.js:router]`): Admin-only endpoints for accounts (`GET/POST /accounts`, `POST /accounts/:id/convert`, `POST /accounts/:id/payments`), financial reporting (`GET /report`), accounting journal (`GET/POST /journal`), banking (`GET /bank`, `POST /bank/import`, `POST /bank/:id/match`), inventory & assets (`GET /stock`, `POST /items`, `POST /items/:id/limits`, `POST /lots`, `POST /lots/:id/movements`, `POST /suppliers`, `POST /orders`, `POST /assets`, `POST /assets/:id/maintenance`), and fiscal XML archive (`GET /invoices`, `GET /invoices/:id/xml`, `POST /invoices`).
- Patient clinical record router (`[patient.routes.js:router]`): Authenticated `POST /register/patientDetails`, `POST /register/histo`, `POST /register/clinicalRecord`, `GET /get/patientDetails`, `GET /get/histo`.
- Procedure router (`[procedure.routes.js:router]`): Authenticated `GET /user/procedures`; admin-only `POST /procedures`, `GET /admin/patients`, `GET /admin/procedures/:patientId`.

## Invariants
- Route protection boundaries (`[appointment.routes.js:router]`, `[auth.routes.js:router]`, `[contact.routes.js:router]`, `[patient.routes.js:router]`, `[procedure.routes.js:router]`, `[operations.routes.js:router]`, `[invoiceRequest.routes.js:router]`): All user-private endpoints run `authMiddleware`; all `/admin/*`, `/procedures`, and operations routes run `authMiddleware` followed by `adminMiddleware`; Mercado Pago `POST /webhook` bypasses `authMiddleware` and relies on controller signature/SDK verification.
- Invoice request eligibility & idempotency (`[invoiceRequest.routes.js:approvedOnlinePayment]`, `[invoiceRequest.routes.js:receiver]`, `[invoiceRequest.routes.js:router]`): Rejects non-ObjectId or non-owned appointment IDs with HTTP `404`; requires `status` in `['Confirmed', 'Completed']`, `paymentMode` in `['full', 'partial']`, and positive `amountExpected` (else HTTP `409`); validates SAT/CFDI receiver regex formats (`rfc`, `name`, `postalCode`, `taxRegime`, `cfdiUse`, else HTTP `400`); enforces single immutable snapshot per appointment via `$setOnInsert` and sets `Cache-Control: no-store`.
- Operations validation & integrity (`[operations.routes.js:money]`, `[operations.routes.js:date]`, `[operations.routes.js:requestKey]`, `[operations.routes.js:today]`, `[operations.routes.js:router]`): Requires JSON object bodies on `POST`; stores money as integer cents from decimal strings; validates dates as `YYYY-MM-DD` against `America/Mexico_City`; enforces UUID `requestKey` idempotency on account payments and lot movements; limits bank imports to 1–500 non-zero rows; requires bank reconciliation matches to use `channel === 'bank'`, matching signed amount (`sale` positive, expenses negative), and `<= 3` days delta; disallows future lot movements, backdating prior to last movement, consuming expired lots, or linking procedures to non-`use` movements; `POST /orders` auto-computes `quantity = item.maximum - stock` (non-expired lots only) when `quantity === null` and derives `arrival = issued + supplier.leadDays`; `POST /assets/:id/maintenance` rejects future `date`, `next <= performed`, or dates earlier than the previous service; `POST /journal` rejects future `date` or `debit === credit` and `GET /journal` caps results at `100`; `GET /report` rejects `to < from || to > today()` and passes `to` as the `today` argument into `report(rows, from, to, to, entries)`; serves archived fiscal XML strictly as `application/octet-stream` downloads without parsing; translates Mongoose `VersionError`/code `11000` to HTTP `409` and `CastError`/`ValidationError` to HTTP `400`.

## Side Effects
- Delegates HTTP requests to Back-End controllers and performs direct MongoDB reads/writes on `Appointment`, `InvoiceRequest`, `Procedure`, and the nine `models/operations` collections (`[invoiceRequest.routes.js:router]`, `[operations.routes.js:router]`).
- Calls `Bank.init()` before reconciling bank movements (`[operations.routes.js:router]`) and triggers `Bank.bulkWrite` upserts during statement imports.
- Sets HTTP response headers (`Cache-Control: no-store` in `[invoiceRequest.routes.js:router]`; `Content-Disposition` attachment and `application/octet-stream` in `[operations.routes.js:router]`).
