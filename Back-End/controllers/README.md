# Back-End Controllers

## Overview
Implements Express route handler logic for appointment scheduling and availability, user authentication and recovery, contact submissions, Mercado Pago checkout and webhooks, patient clinical records, and dental procedure tracking.

## Interface
- Appointments (`[appointment.controller.js:module.exports]`): `cleanupExpiredReservations`, `createAppointment`, `getTreatments`, `getUserAppointments`, `getUserAppointmentById`, `getAllAppointments`, `cancelAppointment`, `getAvailability`, `blockSlot`, `unblockSlot`, `blockRange`, `unblockRange`.
- Authentication (`[auth.controller.js:module.exports]`): `register`, `login`, `getProfile`, `googleLogin`, `setPatientType`, `verifyEmail`, `resendVerificationEmail`, `forgotPassword`, `resetPassword`.
- Contact (`[contact.controller.js:module.exports]`): `submitContactForm`.
- Payments (`[mercado_pago.controller.js:module.exports]`): `val`, `proccesPay`, `receiveWebhook`.
- Clinical records (`[patient.controller.js:module.exports]`): `upsertPatientDetails`, `upsertMedicalHistory`, `saveCompleteClinicalRecord`, `getPatientDetails`, `getMedicalHistory`.
- Procedures (`[procedure.controller.js:module.exports]`): `createProcedure`, `getMyProcedures`, `getPatientProcedures`, `listPatients`.

## Invariants
- Mandatory JWT configuration (`[auth.controller.js:jwtSecret]`): Throws an error at module load time if `process.env.JWT_SECRET` is missing; issued JWTs expire in `'1h'` (`[auth.controller.js:login]`, `[auth.controller.js:googleLogin]`).
- Account verification & anti-enumeration (`[auth.controller.js:register]`, `[auth.controller.js:login]`, `[auth.controller.js:googleLogin]`, `[auth.controller.js:verifyEmail]`, `[auth.controller.js:setPatientType]`, `[auth.controller.js:forgotPassword]`, `[auth.controller.js:resetPassword]`): `register` rejects duplicate emails with HTTP `409` and issues a 32-byte hex `verificationToken`; `verifyEmail` returns HTML (not JSON) linking to `${FRONTEND_URL}/log-in`; password login requires `user.isVerified === true` (HTTP `401`); `googleLogin` requires `GOOGLE_CLIENT_ID` (HTTP `503`), Google's `email_verified === true` (HTTP `401`, without re-checking Dental One `user.isVerified`), and returns HTTP `404` (`needRegister: true`) for unregistered emails; `setPatientType('new')` resets `canPayAtClinic` to `false`; `forgotPassword` returns HTTP `200` whether or not the email exists and sets a 1-hour `resetPasswordExpires`; `resetPassword` requires a non-expired token.
- Appointment creation, availability & slot blocks (`[appointment.controller.js:createAppointment]`, `[appointment.controller.js:getAvailability]`, `[appointment.controller.js:blockRange]`, `[appointment.controller.js:unblockRange]`, `[appointment.controller.js:ALLOWED_CREATE_STATUSES]`): Ignores client-supplied `durationMinutes`, `providerName`, and `price`, resolving them from `findTreatment(reason)`; restricts initial `status` to `['Scheduled', 'Pending_Clinic_Payment']`; requires `owner.canPayAtClinic === true` for `'Pending_Clinic_Payment'` (HTTP `403`); rejects blocked slots and specialist overlaps with HTTP `409`; sets `expiresAt` to `RESERVATION_MINUTES` (`15` min) for online-payment appointments and formats the WhatsApp reminder `magicLink` to `${FRONTEND_URL}/paciente`. `getAvailability` validates `from`/`to` dates as `YYYY-MM-DD`, defaults `from` to yesterday UTC (`UTCDate - 1`), and anonymizes occupied slots (`mine: false` for admins). `blockRange` and `unblockRange` require `endHour > startHour` in 30-minute increments via `buildSlots`.
- Appointment access & cancellation guards (`[appointment.controller.js:getUserAppointmentById]`, `[appointment.controller.js:cancelAppointment]`): Validates MongoDB ObjectId (HTTP `400`), returns `404` if owned by another non-admin user, and forbids canceling `'Confirmed'` or `'Completed'` appointments (HTTP `400`).
- Payment integrity & webhook idempotency (`[mercado_pago.controller.js:verifyWebhookSignature]`, `[mercado_pago.controller.js:proccesPay]`, `[mercado_pago.controller.js:receiveWebhook]`): `proccesPay` enforces appointment ownership (HTTP `403`), restricts payable statuses to `['Scheduled', 'Payment_Pending']`, rejects expired `expiresAt`, and derives `amountExpected` from server catalog pricing; `receiveWebhook` validates HMAC-SHA256 `x-signature` when `MP_WEBHOOK_SECRET` is configured (HTTP `401` on failure), ignores updates to `'Confirmed'`/`'Completed'` appointments, checks schedule conflicts before reactivating `INACTIVE_STATUSES`, requires `Math.abs(cobrado - esperado) < 0.01` before confirming, handles `'pending'`/`'in_process'` (setting `'Payment_Pending'` and extending `expiresAt` via `pendingPaymentDeadline`) and `'rejected'` (setting `'Payment_Failed'`, unsetting `expiresAt`, and sending `pagoRechazado` email), and always returns HTTP `200` after signature verification so Mercado Pago stops retrying.
- Patient record ownership & normalization (`[patient.controller.js:sinCamposProtegidos]`, `[patient.controller.js:normalizarHistorial]`, `[patient.controller.js:upsertPatientDetails]`, `[patient.controller.js:upsertMedicalHistory]`, `[patient.controller.js:saveCompleteClinicalRecord]`): Strips `_id`, `user`, and `email` from request payloads so documents always bind to `req.user.id`; maps `tratamientoMedicoActual` to `tratamiendoMedicoActual` in medical histories via `normalizarHistorial`; keeps `User.patientDetails` synchronized with `PatientDetails._id`.
- Admin-only procedure routes (`[procedure.controller.js:createProcedure]`, `[procedure.controller.js:getPatientProcedures]`, `[procedure.controller.js:listPatients]`): Reject non-admin callers with HTTP `403`; `createProcedure` splits comma-separated string `procedimientos` and resolves patients by `patientId` or lowercased `patientEmail`; `listPatients` excludes `role: 'admin'`.

## Side Effects
- Reads and writes MongoDB collections `User`, `Appointment`, `BlockedSlot`, `Contact`, `PatientDetails`, `MedicalHistory`, and `Procedure` (including MongoDB transactions when available in `[patient.controller.js:saveCompleteClinicalRecord]` and bulk writes in `[appointment.controller.js:blockRange]`).
- Checks local filesystem for `GOOGLE_CALENDAR_KEYFILE` (or `../google-calendar-prueba.json`) at module load and inserts events into Google Calendar via `calendar.events.insert` when enabled (`[appointment.controller.js:GOOGLE_ENABLED]`, `[appointment.controller.js:createAppointment]`).
- Calls external APIs: Google OAuth token verification (`[auth.controller.js:googleLogin]`), Mercado Pago `Preference.create` (`[mercado_pago.controller.js:proccesPay]`) and `Payment.get` (`[mercado_pago.controller.js:receiveWebhook]`), Twilio WhatsApp reminders (`[appointment.controller.js:createAppointment]`), and fire-and-forget SMTP/Resend/Gmail-API email sends across appointment, auth, contact, and payment flows.
- Unlocks `User.canPayAtClinic = true` upon approved payment (`[mercado_pago.controller.js:receiveWebhook]`) or when selecting `'returning'` (`[auth.controller.js:setPatientType]`).
